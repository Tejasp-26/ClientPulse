# ClientPulse v2

**B2B client churn and health predictor for customer success teams.**

> ⚠️ **Important – read before sharing results:**
> The training data is **synthetic** (generated by `data/generate_data.py`). The churn label is planted by the generator, not observed from real clients. Metrics show the pipeline works; they do not measure real-world accuracy. Risk % is a **ranking score**, not a calibrated probability.

---

## What it does

A user uploads monthly client usage data. ClientPulse:
1. Stores the history in SQLite (upload only the new month after the first time).
2. Predicts which clients may leave and explains the warning signs.
3. Suggests actions for account managers.
4. Estimates revenue at risk and potential savings.
5. Saves each analysis run and user feedback so predictions can be compared with real outcomes later.

## Architecture

```
USER (browser)
   ↓
FRONTEND: Streamlit (frontend/app.py)  ── HTTP ──┐
                                                  ↓
BACKEND: FastAPI (backend/main.py + routers/)
   ↓ calls
ML CORE: ml/ (features, explain, actions, utils, llm_note, train)
   ↓ reads / writes
STORAGE: SQLite (db/clientpulse.db) + models/model.pkl + models/metrics.json
```

Streamlit **never** touches the database or the model directly — it calls FastAPI endpoints.

## How to run

### 1. Create a virtual environment (Python 3.11)

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# Mac/Linux
source venv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Generate training data and train the model (one time)

```bash
python data/generate_data.py
python ml/train.py
```

### 4. Generate sample demo data (one time)

```bash
python data/make_sample.py
```

### 5. Start the API

```bash
uvicorn backend.main:app --reload --port 8000
```

API docs: http://127.0.0.1:8000/docs

### 6. Start the Streamlit frontend (new terminal)

```bash
streamlit run frontend/app.py
```

## Limitations

- Data is synthetic; churn label is planted by the generator.
- Small test set (~18 churners in test split); scores can shift a few points.
- Random split, not time-based.
- No cross-validation, no hyperparameter tuning, no probability calibration.
- Risk % is a ranking score, not a true probability.
- SHAP explains the model, not real-world causes.
- Impact numbers are estimates from user-set assumptions.
- SQLite is single-user; no authentication.
- Model is not retrained from stored data or feedback.
- History arrives by file upload, not a live data connection.
